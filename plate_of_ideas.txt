1. The Session Manager (Identity Logic)
The Switch: Move from asking for a name in every function to a "Login Once" system.

The Global State: Create a variable (like current_user) at the top of your main() loop that starts as None.

The Persistence: Once a user logs in, that variable holds their name for the entire duration of the program.

The Logout: Add an "Exit/Logout" menu option that sets the variable back to None, effectively making the program "of no one" again.

2. In-Memory Data Sync (Performance Logic)
The Load: On login, search the data_customer.csv and pull the user’s specific data (points, books borrowed) into a local Python List.

The Cache: All "good stuff" (adding points, borrowing books) happens to this local list in memory, not the file.

The Dump: To prevent breaking the system, only overwrite the data_customer.csv when the user selects "Exit" or "Logout".

3. Option B: Mood-Based Recommendations (UX Logic)
The Trigger: This happens automatically the moment a user successfully logs in.

The Randomizer: Use df.sample() to pick one random book from your inventory.

The Interaction: Combine the employeeMaster mood with the random book to give a personalized greeting: "Hey {name}, I'm feeling {mood} today, you should check out {book}!"

4. Loyalty "BOGO" Perk (Reward Logic)
The Threshold: Set a loyalty point requirement (e.g., 5 points).

The Trigger: Inside the "Purchase" function, check the user's points in their local list.

The Reward: If they have enough points, trigger a "Buy One, Get One" event where they can select two books for the price of one, decreasing the stock for both in the inventory.

5. Structural "Open Heart Surgery" (Refactor Plan)
Function Parameters: Change functions like bookBorrow() to bookBorrow(user_data) so they use the session list instead of looking at the CSV.

The Bridge: Keep your existing CSV logic but wrap it in a single "Save" function that runs at the end of the session.
